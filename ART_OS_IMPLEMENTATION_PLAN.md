## 🔑 КЛЮЧЕВЫЕ ПРИНЦИПЫ АРХИТЕКТУРЫ

### 1. Event-Driven Architecture (EDA)
- **Все взаимодействия через события** (Kafka topics)
- **Асинхронная обработка** для высокой производительности
- **Независимость компонентов** - каждый сервис автономен

### 2. Гибридная БД (Neo4j + Memgraph)
- **Neo4j** - "Архив" (долговременное хранение на SSD)
- **Memgraph** - "Мозг" (быстрые операции в RAM)
- **Синхронизация через Kafka** с событием NEW_ASSET

### 3. Таблицы Связей (Link Tables)
Вместо чистого графа используем реляционную модель для ACID-гарантий:

```sql
-- Пример: Таблица владения
CREATE TABLE ownership_link (
    id UUID PRIMARY KEY,
    owner_id UUID REFERENCES persons(id),
    asset_id UUID REFERENCES assets(id),
    start_date TIMESTAMP,
    end_date TIMESTAMP,
    is_active BOOLEAN DEFAULT TRUE,
    provenance_index INTEGER,
    CONSTRAINT unique_active_owner UNIQUE (asset_id, is_active)
);
```

### 4. Circuit Breaker (STOP Mechanism)
При получении отрицательного ответа от любого блока:
- **Компенсирующие транзакции** (Saga Pattern)
- **Откат всех изменений**
- **Уведомление инициатора**

## 📊 СТРУКТУРА ГРАФА ДАННЫХ

### Основные Узлы (Nodes):

| Узел | Описание | Свойства |
|------|----------|----------|
| **Asset** | Произведение искусства | id, name, creation_year, base_price, status |
| **Person** | Художник/Коллекционер | id, name, bio, reputation_score |
| **Entity** | Банк/Галерея/Маркетплейс | id, name, type, license_key |
| **Transaction** | Сделка | id, price, timestamp, type, status |
| **MediaItem** | Новость/Статья | id, title, sentiment_score, url |
| **Event** | Выставка/Аукцион | id, date, location, importance_level |

### Типы Связей (Edges):

- `(Person)-[:CREATED]->(Asset)` - Авторство
- `(Entity:Gallery)-[:REPRESENTS]->(Person:Artist)` - Представительство
- `(Person)-[:OWNS]->(Asset)` - Владение (с provenance_index)
- `(Asset)-[:SOLD_VIA]->(Transaction)` - История продаж
- `(MediaItem)-[:MENTIONS]->(Asset/Person)` - Медийное влияние
- `(Transaction)-[:PROCESSED_BY]->(Entity)` - Обработка сделки

## 🧠 АНАЛИТИЧЕСКИЙ ЦЕНТР

### Технологический стек:
- **Язык**: Python 3.11+
- **Фреймворк**: FastAPI (асинхронный)
- **Математика**: NumPy, Pandas, SciPy, Scikit-learn
- **Граф**: neo4j-python-driver / memgraph-python-driver

### Алгоритм KDE (Kernel Density Estimation):

Вычисляет "гравитацию" рынка - справедливую цену на основе:
1. **Исторические цены** аналогичных активов
2. **Репутационные метрики** (W_trust)
3. **Медийное влияние** (упоминания в новостях)
4. **Контекст событий** (выставки, премии)

### Триггеры активации:

1. **Периодический пересчет** (Batch) - раз в час/сутки
2. **Событийный триггер** - при новой сделке (event TRADE_CREATED)
3. **Персональный запрос** (On-demand) - кнопка "Оценить"

### API Endpoints:

```python

{
  "asset_id": "uuid",

{

  "risk_score": 0.23,

}
```

## 📨 МАРШРУТИЗАТОР СОБЫТИЙ

### Технологии:
- **Язык**: Go (Golang) - для высокой производительности
- **Message Broker**: Apache Kafka / RabbitMQ
- **API Gateway**: gRPC + REST

### Основные задачи:

1. **Прием запросов** от внешних платформ
2. **Валидация JWT** токенов
3. **Публикация событий** в Kafka topics
4. **Оркестрация** ответов от сервисов
5. **Агрегация результатов**
6. **Circuit Breaker** - остановка при ошибках

### Kafka Topics:

```
tx.requests          - Запросы на транзакции
tx.result            - Результаты транзакций
analytics.requests   - Запросы на аналитику
analytics.result     - Результаты аналитики
media.events         - События из медиа
graph.updates        - Обновления графа
system.stop          - Критические ошибки (STOP)
```

### Механизм STOP:

```go
// Псевдокод Circuit Breaker
func (r *Router) ProcessTransaction(tx Transaction) error {
    // 1. Параллельная отправка
    analyticsResponse := r.SendToAnalytics(tx)
    transResponse := r.SendToTransHub(tx)
    
    // 2. Проверка ответов
    if analyticsResponse.Status == "REJECT" || 
       transResponse.Status == "ERROR" {
        // 3. STOP - откат всех изменений
        r.PublishToTopic("system.stop", tx.ID)
        r.CompensateTransaction(tx)
        return errors.New("Transaction rejected")
    }
    
    // 4. Commit в граф
    r.CommitToGraph(tx)
    return nil
}
```

## 💸 ТРАНЗАКЦИОННЫЙ ХАБ

### Технологии:
- **Язык**: Go (для надежности)
- **Pattern**: Saga Pattern (компенсирующие транзакции)
- **БД**: PostgreSQL (ACID гарантии)

### Два потока сделок:

1. **P2P (Peer-to-Peer)** - прямые продажи
2. **Auction** - аукционные торги

### Saga Pattern - Пример:

```
Шаг 1: RESERVE_ASSET     → Компенсация: RELEASE_ASSET
Шаг 2: BLOCK_FUNDS       → Компенсация: UNBLOCK_FUNDS
Шаг 3: VERIFY_PROVENANCE → Компенсация: -
Шаг 4: TRANSFER_OWNERSHIP → Компенсация: REVERT_OWNERSHIP
Шаг 5: COMPLETE_PAYMENT  → Компенсация: REFUND_PAYMENT
```

При ошибке на любом шаге - выполняются компенсирующие действия в обратном порядке.

## 🔐 БЕЗОПАСНОСТЬ

### Многоуровневая защита:

1. **Identity Layer** (JWT + OAuth2)
   - Токены с 24-часовым TTL
   - Refresh tokens для продления
   
2. **Шифрование** (TLS 1.3)
   - Все передачи данных зашифрованы
   - End-to-end encryption для критичных данных

3. **Неизменяемость** (Integrity)
   - Цифровые подписи галерей
   - Blockchain дублирование критичных сделок
   - Хэш-суммы для проверки Data_Corruption

4. **Access Control** (RBAC)
   - Банки видят только свои ветки графа
   - Галереи имеют ограниченный доступ
   - Маркетплейсы не видят конфиденциальные данные
